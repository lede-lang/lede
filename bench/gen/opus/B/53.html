Restore the ledger database to a point in time

  • Databaseledger-prod
  • EnginePostgreSQL on RDS
  • Size1.8 TB
  • Restore time~65 min + validation
!

Never restore over ledger-prod.Restoring over ledger-prod destroys every transaction since the target time. Always restore to a new instance, then repair production from it.

When to use

✓ Use this runbook for

  • Data corruption
  • A bad batch job

✕ Never for

  • A simple instance failover

Written approval required from both the data owner and the on-call lead before you start. This procedure runs under audit.

Before you start

  • Confirm the exact target timestamp, in UTC.
  • Confirm that automated backups cover that timestamp. Retention is 14 days.
  • Freeze the nightly posting job.
  • Open a change record.

Restore steps

  1. Restore to a NEW instance named ledger-restore-YYYYMMDD NEVER OVER PRODUCTION

    • aChoose the target time.
    • bUse the same parameter group, ledger-pg15-prod.
    • cPlace it in the isolated recovery subnet group.

  2. Wait until the instance is available about 65 min

  3. Validate

    • aRow counts of postings and accounts match the expected figures within 0.01%.
    • bThe sum of ledger debits equals the sum of credits.
    • cTwo senior engineers sign off in the change record.

  4. Repair

    • aExport the affected rows from the restored copy.
    • bApply them to production in a transaction reviewed by a second engineer.

  5. Clean up

    • aKeep the restored instance for 7 days.
    • bThen delete it and record the deletion.
