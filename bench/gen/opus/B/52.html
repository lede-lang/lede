search-prod cluster is red

SymptomsTriageFix by causeEscalation

1Symptoms

  • CLUSTER_RED alert firesThe page that brought you here.
  • Partial or empty search resultsArticle search and the archive return less than they should, or nothing.
  • New articles missingEditors report that newly published articles do not appear.

2Triage

  1. Check cluster health and note the number of unassigned shards. 
    GET _cluster/health
  2. Ask the cluster why shards are unassigned. 
    GET _cluster/allocation/explain
  3. Match the explanation to a cause. The usual three:
    • Disk watermarks reached
    • A lost data node
    • A bad index template after a deploy
    Low85%
    High90%
    Flood stage95%

3Fix by cause

!

Before you delete anythingNever delete an index without a snapshot taken in the last 24 hours. The archive cannot be rebuilt.

1Disk watermark

  1. a

    Find the fullest nodes.

    GET _cat/allocation?v
  2. b

    Delete indices older than 90 days from the logs-* family.

    Snapshot check first: confirm a snapshot from the last 24 hours exists before deleting any index.

    Never touch articles-* or archive-*.

  3. c

    Once disk is under 80%, clear the read-only block.

    PUT _all/_settings
{
  "index.blocks.read_only_allow_delete": null
}
  4. d

    Wait for the shards to relocate.

2Lost data node

  1. a

    Check the instance in the AWS console.

  2. b

    If it is gone, let the autoscaling group replace it. usually 6–8 min

  3. c

    Shard recovery then runs for the 1.2 TB on each node. about 20 min

3Bad index template

  1. a

    Find the last deploy in #deploys.

  2. b

    Roll the template back using the saved copy in the search-config repository.

  3. c

    Reindex the affected index.

4Escalation

Still red after 30 minutes?

  1. Page the Search Infrastructure lead.
  2. Open an incident in #incidents.
