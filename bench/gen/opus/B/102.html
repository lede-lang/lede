How a register sale reaches the online stock count

For new engineers: the path from a store's point of sale to the stock number shoppers see online, and what happens when a store goes offline.

Retail Platform team2026-10-08
Source of truthThe Stock Ledger is the only source of truth for stock. Every other count is a copy.
Expect lagThe Storefront count may lag the ledger by up to 20 seconds.

Sale-to-stock sequence

Swipe sideways to see all five participants.

  1. Store POS → Edge Sync Agent: “sale recorded, 2 units of SKU 48113”
  2. Edge Sync Agent → Inventory API: POST /adjustments, batched every 5 seconds
  3. Inventory API → Stock Ledger: append decrement
  4. Stock Ledger → Inventory API: new on-hand count
  5. Inventory API → Edge Sync Agent: 202 Accepted
  6. Inventory API → Storefront: publish stock change
Offline case. When the store loses its connection, the Store POS keeps selling and the Edge Sync Agent keeps the adjustments in a local queue. When the link returns, it sends them to the Inventory API in order as “replay queued adjustments”.

Good to know

4 hours

The local queue holds up to 4 hours of sales, about 3000 adjustments at a busy store.

No double counts

Every adjustment carries an idempotency key, so replays never count a sale twice.

15 minutes

Online orders reserve stock for 15 minutes at checkout.
