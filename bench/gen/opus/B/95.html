The dispatch-jobs queue is backing up

Owner
Dispatch Engineering
Alert
QUEUE_DEPTH_HIGH
Queue
dispatch-jobs
Never purge dispatch-jobs.Every message is a real customer delivery. Purging deletes deliveries that customers are waiting for. Drain the queue; do not empty it.

Symptoms

Normal Alert
400 5,000

Queue depth, 0 to 6,000 messages, drawn to scale.

Alert fires

QUEUE_DEPTH_HIGH fires when depth stays above 5,000 for 10 minutes. Normal is under 400.

Drivers notice

New jobs arrive late in the driver app.

Diagnose

  • Queue depth and consumer count

    kubectl -n dispatch get hpa dispatch-consumer

  • Oldest message age

    Check it on the queue dashboard.

  • Database connection pool

    Capped at 200 connections. This is what limits how far consumers can scale.

Fix steps

  1. Scale the consumers

    1. a
      Run:
      kubectl -n dispatch scale deploy dispatch-consumer --replicas=24
    2. b
      Wait 5 minutes and re-check.
    3. c
      If depth is still rising, scale to 40. That is the maximum the database pool supports; do not go higher.
    24 replicas5 min, still rising?40 max

  2. Check for poison messages

    1. a
      If one message has been retried more than 10 times,
    2. b
      move it to dispatch-dlq with the dlq-move tool.

  3. Pause the bulk import scheduler

    In the admin console. Bulk imports add up to 3,000 jobs at a time.

  4. Re-enable the scheduler gradually

    Only when depth drops under 400.

Escalation

Still above 5,000 after 20 minutes?

Page the Dispatch Engineering lead and open an incident in #incidents.
