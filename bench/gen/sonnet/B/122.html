Rolling Back a Bad Client Patch: Drift Harbor

  • Owner: Live Ops
  • Version 2026-10-13
  • Last good build: 4.12.3
Check this first

Rolling back after a database schema migration corrupts player inventories. If the patch contained a migration, do not roll back. See "Do not roll back if" below.

When to roll back

After a patch release, roll back if either of these holds:

> 2%
of sessions crash, for 15 minutes
OR
> 5%
login failures, for 10 minutes

The Live Ops lead must approve in the #liveops-war-room channel before you start.

Do not roll back if

Schema migration in the patch

The patch contained a database schema migration, such as migration 0087 in patch 4.13. Older clients cannot read the new schema.

Go forward with a hotfix instead.

Rollback steps

  1. Stop the bleeding
    1. Pause the deploy pipeline.
    2. Set matchmaking to maintenance mode with the in-game message Back soon.
  2. Point players to the last good build
    1. In the release console, set the live manifest to build 4.12.3.
    2. Invalidate the CDN cache, which takes about 10 minutes.
  3. Verify
    1. Install the build on 3 test accounts, one each on PC, console and mobile.
    2. Confirm login and a full match.
  4. Reopen in stages
    1. Let in 10 percent of players.
    2. 25 percent after 5 minutes.
    3. 50 percent after 5 more minutes.
    4. 100 percent after another 5 minutes, if the crash rate stays under 1 percent.
    10%start
    25%+5 min
    50%+10 min
    100%+15 min, if crash rate < 1%
  5. Communicate
    1. Post a status update within 30 minutes of the decision.
    2. Schedule compensation of 500 gems for every active account.
