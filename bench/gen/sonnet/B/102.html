How a register sale reaches the online stock count

Written by the Retail Platform team · 2026-10-08 · For new engineers

Remember two things. The Stock Ledger is the only source of truth for stock. The Storefront count may lag by up to 20 seconds, so a number that looks stale is usually just in flight.

Sale-to-stock sequence

Five participants take part. Solid arrows are requests; dashed arrows are replies. The diagram scrolls sideways on narrow screens, and the same steps are written out below it.

The same steps in words

  1. Store POS tells Edge Sync Agent: sale recorded, 2 units of SKU 48113.
  2. Edge Sync Agent calls Inventory API: POST /adjustments, batched every 5 seconds.
  3. Inventory API tells Stock Ledger: append decrement.
  4. Stock Ledger answers Inventory API: new on-hand count.
  5. Inventory API answers Edge Sync Agent: 202 Accepted.
  6. Inventory API tells Storefront: publish stock change.

When the store is offline

If the store loses its connection, Store POS keeps selling. Edge Sync Agent keeps the adjustments in a local queue, then sends them in order when the link returns, as replay queued adjustments to Inventory API. From there the path is the same as above.

Timing budget

Bars are laid end to end. If every hop used its full limit, the total would be about 16.2 seconds, inside the 20-second end-to-end target.

Good to know

The queue is deep

The local queue holds up to 4 hours of sales, which is about 3000 adjustments at a busy store.

Replays are safe

Adjustments carry an idempotency key, so replays never double count.

Carts reserve stock

Online orders reserve stock for 15 minutes at checkout.
