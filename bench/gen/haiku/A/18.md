# Postmortem: sales dashboards late on 2026-10-02

Analytics Platform team, Juniper Retail.

## Impact

- 9 hours of delay on the daily sales dashboards, which are normally ready by 02:00.
- 23 dashboards were stale.
- The 08:00 executive sales report went out with the previous day's numbers.

## Timeline

| Time | Event |
|---|---|
| 01:00 | Nightly Spark Job starts |
| 01:47 | Spark Job fails with out-of-memory on the orders partition for 2026-10-01 |
| 02:30 | Automatic retry also fails |
| 07:55 | Analyst reports stale dashboards |
| 08:20 | On-call doubles executor memory to 16 GB and reruns |
| 10:05 | Spark Job succeeds |
| 10:58 | Dashboards refreshed |

## Root cause

A promotion produced 3.4 times the normal order volume: 4.1 million orders against a typical 1.2 million. The executors had 8 GB each, which was not enough for the larger partition. The job ran out of memory on every attempt.

## Lessons learned

**What went well**

- The analyst who spotted the stale dashboards raised it quickly.
- The fix was a memory change and a rerun, so recovery was fast once the cause was known.

**What did not go well**

- The nightly job failed twice, and no one was paged after the first failure.
- Executor memory was fixed and did not scale with the input volume.
- Dashboards gave no sign that their data was stale.

## Action items

1. Page on-call when the nightly job fails twice.
2. Size executor memory from the input volume.
3. Add a data freshness banner to dashboards.
