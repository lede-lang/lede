Runbook: restore ledger-prod to a point in time

Core Systems team · database ledger-prod (PostgreSQL on RDS, 1.8 TB) · a restore takes roughly 65 minutes plus validation

When to use

  • Data corruption, or a bad batch job.
  • Never for a simple instance failover.
  • Only with written approval from both the data owner and the on-call lead.
Do not restore over ledger-prod. Restoring over ledger-prod destroys every transaction since the target time. Always restore to a new instance.

Before you start

  • Confirm the exact target timestamp in UTC.
  • Confirm that automated backups cover it. Retention is 14 days.
  • Freeze the nightly posting job.
  • Open a change record.

Restore steps

  1. Restore to a NEW instance named ledger-restore-YYYYMMDD. Never restore over production.
    1. Choose the target time.
    2. Use the same parameter group, ledger-pg15-prod.
    3. Place the instance in the isolated recovery subnet group.
  2. Wait until the instance is available. This takes about 65 minutes.
  3. Validate the restored copy.
    1. Row counts of postings and accounts match the expected figures within 0.01 percent.
    2. The sum of ledger debits equals the sum of credits.
    3. Two senior engineers sign off in the change record.
  4. Repair production.
    1. Export the affected rows from the restored copy.
    2. Apply them to production in a transaction reviewed by a second engineer.
  5. Clean up.
    1. Keep the restored instance for 7 days.
    2. Then delete it and record the deletion.
