Postmortem · Analytics Platform

Daily sales dashboards were 9 hours late on 2026-10-02

Juniper Retail · Analytics Platform team

Impact

  • 9 hours of delay to the daily sales dashboards, which are normally ready by 02:00.
  • 23 dashboards were stale for the morning.
  • The 08:00 executive sales report went out with the previous day's numbers.

Pipeline

Timeline

TimeEvent
01:00Nightly Spark Job starts
01:47Spark Job fails with out-of-memory on the orders partition for 2026-10-01
02:30Automatic retry also fails
07:55Analyst reports stale dashboards
08:20On-call doubles executor memory to 16 GB and reruns
10:05Spark Job succeeds
10:58Dashboards refreshed

Root cause

A promotion produced 3.4 times the normal order volume: 4.1 million orders against a typical 1.2 million. The executors still had 8 GB each, which was not enough to hold the orders partition in memory, so the job ran out of memory on both attempts.

Lessons learned

What went well

  • The analyst reported the stale dashboards quickly.
  • The rerun with more memory finished the same morning.

What did not go well

  • The failed nightly job did not page anyone.
  • Dashboards gave no warning that their data was stale.

Action items

  1. Page on-call when the nightly job fails twice.
  2. Size executor memory from the input volume.
  3. Add a data freshness banner to dashboards.
Context The fix that worked was manual. The automatic retry used the same memory settings, so it failed the same way.
