Runbook: search-prod cluster is red

Quarry Press · OpenSearch cluster search-prod (nine nodes) · serves article search and the subscriber archive

Symptoms

  • The CLUSTER_RED alert fires.
  • Search returns partial or empty results.
  • Editors report that new articles do not appear.

Triage

  1. Check cluster health and note the number of unassigned shards. 
    GET _cluster/health
  2. Ask the cluster why shards are not assigned. 
    GET _cluster/allocation/explain

The usual causes are:

  • Disk watermarks: low 85 percent, high 90 percent, flood stage 95 percent.
  • A lost data node.
  • A bad index template after a deploy.

Fix by cause

Before any deletion: never delete an index without a snapshot taken in the last 24 hours. The archive cannot be rebuilt. Never touch articles-* or archive-* indices.

1. Disk watermark

  1. Find the fullest nodes. 
    GET _cat/allocation?v
  2. Delete indices older than 90 days from the logs-* family only. Never delete from articles-* or archive-*.
  3. Once disk is under 80 percent, clear the read-only block. 
    PUT _all/_settings
{"index.blocks.read_only_allow_delete": null}
  4. Wait for the shards to relocate.

2. Lost data node

  1. Check the instance in the AWS console.
  2. If it is gone, let the autoscaling group replace it. This usually takes 6 to 8 minutes.
  3. Shard recovery then takes about 20 minutes for the 1.2 TB per node.

3. Bad index template

  1. Find the last deploy in #deploys.
  2. Roll the template back using the saved copy in the search-config repository.
  3. Reindex the affected index.

Escalation

  • Page the Search Infrastructure lead if the cluster is still red after 30 minutes.
  • Open an incident in #incidents.
