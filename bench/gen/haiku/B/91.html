Edge proxy TLS certificate rotation

Platform team runbook · Owner: Platform Security · Applies to the 18 edge proxies

CertificatesCover 12 hostnames
Proxies18 total: 1 canary, 17 rollout
AlertCERT_EXPIRY_30D

When to rotate

Rotate when a certificate has 30 days or fewer left. The CERT_EXPIRY_30D alert announces this. The certificates cover 12 hostnames, so the new certificate must list all 12.

Before you start

  • Have the change record open.
  • Confirm that no deploy is running in #deploys.
  • Check that the internal CA is healthy.

Rotation steps

Never delete the old private key before step 6.
  1. Confirm expiry.
    1. Run openssl x509 -enddate -noout on the live certificate.
    2. Compare the date with the alert.
  2. Request the new certificate.
    1. Run certctl request --profile edge-prod.
    2. Check that the output lists all 12 hostnames.
  3. Stage it on the canary proxy only (edge-canary-01).
    1. Copy the new certificate to /etc/edge/certs/next.
    2. Reload the proxy.
  4. Verify the canary.
    1. openssl s_client -connect edge-canary-01:443 shows the new expiry date.
    2. Handshake errors stay under 0.1 percent for 20 minutes.
  5. Roll out to the other 17 proxies in batches of 3, waiting 5 minutes between batches.
  6. Revoke the old certificate after 48 hours, and record the revocation in the change record.

Rollback

The previous certificate stays in /etc/edge/certs/previous for 7 days. To roll back, copy it back into place and reload the proxy.

Escalation

  • If any proxy shows more than 2 percent handshake errors, page Platform Security.
  • Post an update in #platform-sec.
