Postmortem · Analytics Platform

Daily sales dashboards 9 hours late

Juniper Retail · 2026-10-02 · Normally ready by 02:00

Impact

  • 9 hours of delay: dashboards refreshed at 10:58 instead of 02:00.
  • 23 dashboards were stale.
  • The 08:00 executive sales report went out with the previous day's numbers.

Pipeline

Failed component. Dashed arrows: no data delivered downstream until the rerun.

Timeline

TimeEvent

01:47Spark Job fails with out-of-memory on the orders partition for 2026-10-01
02:30Automatic retry also fails
07:55Analyst reports stale dashboards
08:20On-call doubles executor memory to 16 GB and reruns

Root cause

A promotion on 2026-10-01 produced 4.1 million orders, about 3.4 times the typical 1.2 million. The nightly Spark Job processes each day's orders partition with executors sized at 8 GB each, a figure set for normal volume. The oversized partition did not fit in executor memory, so the job failed with out-of-memory, and the automatic retry failed the same way because nothing about its sizing had changed. Doubling executor memory to 16 GB let the rerun complete.

Lessons learned

What went well

  • Once engaged, on-call found the cause and fixed it quickly.
  • Rerunning with more memory needed no code change.
  • The analyst who noticed stale data reported it right away.

What did not

  • Two failures overnight paged no one; a person found the problem six hours later.
  • Executor memory was fixed, not sized to the input volume.
  • Dashboards gave no sign their data was stale.

Action items

  1. Page on-call when the nightly job fails twice.
  2. Size executor memory from the input volume.
  3. Add a data freshness banner to dashboards.
  4. Alert when the job input exceeds 2.5 times the 30-day average.
