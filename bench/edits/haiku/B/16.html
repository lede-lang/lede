Summary

A config change lowered the database connection pool from 200 to 20. Incoming requests queued behind the small pool and then timed out. The change was rolled back, and error rates returned to baseline.

Root cause

The pool size was changed from 200 to 20 in a single config change. Requests then queued for connections until they timed out, which turned into failed requests across the Billing API.

Gap found in review The config linter did not validate pool size bounds, so the bad value passed every check before deploy.
