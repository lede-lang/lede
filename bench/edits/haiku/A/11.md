# AWS landing zone

Cloud Foundations team, Meridian Logistics. Documented as of 2026-10-05.

## Account structure

```mermaid
flowchart LR
    subgraph mgmt["Management account"]
        orgs["AWS Organizations"]
        idc["IAM Identity Center"]
    end

    subgraph security["Security account"]
        guardduty["GuardDuty"]
        hub["Security Hub"]
    end

    subgraph logarchive["Log Archive account"]
        logbucket["Log Archive Bucket"]
    end

    subgraph network["Network account"]
        tgw["Transit Gateway"]
        subgraph egress["Egress VPC"]
            nat["NAT Gateway"]
        end
    end

    subgraph prod["Prod workload account"]
        subgraph prodvpc["Prod VPC"]
            prodapp["Prod App Subnets"]
            proddata["Prod Data Subnets"]
        end
    end

    subgraph dev["Dev workload account"]
        subgraph devvpc["Dev VPC"]
            devapp["Dev App Subnets"]
        end
    end

    subgraph staging["Staging workload account"]
        subgraph stagingvpc["Staging VPC"]
            stagingapp["Staging App Subnets"]
        end
    end

    prodvpc -- "attachment" --> tgw
    devvpc -- "attachment" --> tgw
    stagingvpc -- "attachment" --> tgw
    tgw -- "0.0.0.0/0" --> nat
    guardduty -- "findings" --> hub
    orgs -- "CloudTrail logs" --> logbucket
```

> **Note:** The Prod VPC and Dev VPC cannot route to each other. The Transit Gateway uses separate route tables, `rt-prod` and `rt-dev`.

## Network ranges

| VPC | Account | CIDR | Region |
|---|---|---|---|
| Egress VPC | Network | 10.0.0.0/20 | us-west-2 |
| Prod VPC | Prod workload | 10.10.0.0/16 | us-west-2 |
| Dev VPC | Dev workload | 10.20.0.0/16 | us-west-2 |
| Staging VPC | Staging workload | 10.30.0.0/16 | us-west-2 |

## Guardrails

Service control policies in force across the organization:

- Deny leaving the organization.
- Deny disabling CloudTrail.
- Deny regions other than us-west-2 and us-east-1.
- Deny root user access keys.
