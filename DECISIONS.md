## D1. (internal; recorded in the private planning repo)

## D2. TypeScript run directly by Node (type stripping), no build step in Phase 0
Node 22.18+ strips types natively. Packages export `src/index.ts`, imports use `.ts`
extensions, and `tsc --noEmit` type-checks. Rejected: a tsup/tsc build (slower loop, nothing to
publish yet). Consequence: no enums, namespaces or parameter properties (`erasableSyntaxOnly`).
Phase 1 adds a real build for npm (ROADMAP §1).

## D3. Keyword lines fail loudly; `\` escapes prose
Alternatives: (a) the prototype's "fall back to prose if it doesn't parse"; (b) a sigil on every
directive (`::chart`); (c) loud keywords + escape. (a) hides model mistakes: `chart lien runs`
silently became a paragraph. (b) costs tokens on every directive and is unlike anything models
have seen. (c) costs nothing in the common case because keywords are lowercase and prose
sentences start with a capital; the rare collision is a clear error that names the fix.

## D4. `name:` diagram lines bind only to declared diagrams
Keeps `Note: …` and `Flow: …` as prose. A `x: a -> b` line before `diagram x` is an error,
not prose, because rendering arrow syntax as text is never what the writer meant.

## D5. Grids take a count, not a closing line
`grid 2` holds the next 2 rendered blocks. A closing keyword would break "nothing closes";
"until a blank line" fails because writers put blank lines between blocks. A heading closes a
grid early so a forgotten count can't swallow the next section.

## D6. Multi-line HTML via ```` ```=html ```` fences
Borrowed from Djot/Pandoc raw blocks; models already know fences. Single-line `html:` stays.
Sanitized by default with `sanitize-html` (an allowlist; rejected: writing our own sanitizer).

## D7. CSV quoting: double quotes, `""` escape, `;` row separator
RFC 4180 conventions inside one line. `;` separates rows because a newline cannot.

## D8. Diagrams laid out by elkjs, drawn by the compiler
Brief requirement (no Graphviz, runs in the browser). ELK layered + orthogonal routing +
INCLUDE_CHILDREN for nested groups; edge labels are layout participants, so they get space
instead of overlapping. Visual rules from diagram-design: hairline borders, accent only on
`focus` nodes, mono uppercase edge labels on masks, 4px grid for node sizes, no shadows.

## D9. Phone layouts are computed, not scaled
Charts render twice (640 and 360 wide) and CSS shows one; LR diagrams wider than a phone are
also laid out top-to-bottom. Costs page bytes; buys legible text at 400px with zero JS.
Rejected: scaling one SVG (text shrinks to ~6px) and JS re-layout (breaks zero-JS/CSP).

## D10. Zero executable JavaScript and no remote fetches in the output
Tooltips are SVG `<title>`; chart data tables use `<details>`. Fonts are system stacks
(rejected: Google Fonts by default, which is a remote fetch and a privacy leak). Result: the page
works under `default-src 'none'; style-src 'unsafe-inline'; img-src data: 'self'`.

## D11. Chart palette from the validated dataviz reference
Eight-slot categorical order validated for colorblind-safe adjacent pairs in light and dark.
Text never wears series color; legends appear for ≥2 series and lines get direct end labels.
Number formats are chosen once per chart from the axis magnitude so labels are consistent.

## D12. Benchmark generation through subagents, not the raw API
No `ANTHROPIC_API_KEY` is configured in this environment, so arms were generated by Claude
subagents at two model tiers (`haiku` fast, `opus` frontier) given only the format instructions
and the brief, forbidden from reading other files or validating output. Consequences recorded in
the report: no per-request wall-clock or exact usage; token counts come from a tokenizer
(`@anthropic-ai/tokenizer`, a legacy Claude tokenizer, used only for ratios); API spend is $0.

## D13. Time-to-first-render measured in tokens, not seconds
With no per-request timing, TTFMR is the number of output tokens a model must emit before the
page can show a heading plus one content block (Lede: streaming parser; Markdown: markdown-it on
the prefix; HTML: first closed heading in `<body>` plus one closed element). At a fixed decode
rate seconds are proportional to tokens.

## D14. Arm A gets a good stylesheet and Mermaid
The brief requires it. Markdown is rendered with markdown-it and a GitHub-like stylesheet with
dark mode; ```` ```mermaid ```` blocks (flowchart, sequence, xychart-beta, pie) render with
Mermaid 11 in the browser. Arm B must be self-contained (no CDNs), and the headless browser
blocks all network, so no arm gets resources the others don't.

## D15. Report the draft grammar and the fixed grammar separately; validate fixes on fresh outputs
The first run exposed three grammar problems (column names with spaces, unquoted thousands
separators, edges to groups). Fixing the parser and re-scoring the same outputs would overfit, so
the report gives (1) draft-grammar results on the original outputs, (2) the same outputs under
0.1 for diagnosis only, and (3) **fresh** generations from both models using the updated
model-facing spec as the validity number of record.

## D16. Fidelity is checked on visible text, values on source
Section names and diagram labels must be *visible* (DOM walk that skips `display:none`,
`<title>`, `<desc>`, closed `<details>` bodies, so Lede's accessibility text earns no credit);
data values must appear in the *source*, because a chart's points are not text in any arm.

## D17. Judge model differs from the writers
Pairwise visual judgments use a third model tier (`sonnet`) on blind, side-randomized composites
(desktop light + phone dark), to reduce self-preference.

## D18. Visual judging drove a renderer pass, measured on fresh pages
Round 1 of blind judging preferred hand-written HTML. Fixes and additions went into the
renderer (status pills, value labels, reference lines, step lists, cards, desktop-fitting
diagram direction) with two small grammar additions (`!!!`, `target=`). They were measured
twice: the same pages re-rendered, and fresh pages from the updated spec. The renderer was
tuned on round-1 reasons, so the launch gate requires a held-out task set.

## D19. (internal; recorded in the private planning repo)

## D20. No remote fetch means no remote fetch, through every path
The working-backwards verification found two holes on 2026-10-16: protocol-relative `//`
image sources, and symlinks out of the document folder for `data <`. Image sources must be
relative, `https:` (opt-in) or `data:image`; data files resolve with `realpath` inside the
document's folder, at most 5 MB. Every page also carries a CSP meta as a second layer.

## D35. Pass bar for spike 3, fixed before any v0.4 page is generated
Per tier (Haiku 5.5, Sonnet 5.5, Opus 5.5), each judged against that tier's own HTML on blind pairs, two Sonnet
judge samples per pair, win-or-tie counted as the mean of the two samples. (1) Regression on tasks 71-100 (tuning
data): v0.4 validity >= 98% (<= 0 invalid of 30), and win-or-tie not below the tier's v0.3 value by more than 3 pairs
(10 points); a tier that regresses beyond that fails the change, and the most-used new word for that tier is
ablated before anything is kept. (2) Gate on fresh tasks 101-130: report win-or-tie per tier and per category against
D22's 60%; the headline is the weakest tier, not the average. A tier at or above its v0.3 value but under 60% is
progress, not a pass. No tuning on 101-130 until the verdict is recorded.

## D44. Regions that scroll sideways take keyboard focus (WCAG 2.1.1)

Every such block takes focus, short or not: knowing whether a box overflows needs script, which D10 rules out, and code wraps
at phone width anyway.

## D49. A security corpus gates the renderer; `@accent` is checked for AA text contrast
`packages/render-html/test/fixtures/security-corpus.json` holds 127 injection strings, each written into
31 contexts (meta, headings, prose and links, lists, quotes, notes, code, `html:` and `=html`, chart and table labels, kpi, step,
cards, image alt and caption, flow and sequence diagrams; the 3 strings holding an arrow skip the two diagram contexts, where an
arrow even inside a quoted label reads as an edge), plus 254 single-document cases (link schemes, image sources, sanitizer
bypasses, theme values, diagram options): 378 distinct payloads; 3,931 string-in-context injections in 127 documents, and 254
case documents. Every compiled page is audited with htmlparser2 (already in the lockfile through sanitize-html) and raw-string
checks: no active element, no `on*` attribute, no script URL, `data:` only as `data:image/` on `<img src>`, no remote fetch
without `--allow-remote`, inline styles limited to plain declarations, accent values hex, the CSP meta in place. The audit judges URLs with Node's WHATWG `URL` against an https base and a file:// base, not
with core's `browserUrl`, so a bug in the code under test cannot blind the audit too. Each context carries a marker that must reach the output, and each case
names the errors it expects, so a payload that only fails to parse cannot pass. `fragment` output is the page's `<main>`
byte for byte (a test holds that), so the page audit covers it, less the CSP. When a Chromium resolves, every page also loads
with the CSP removed and JavaScript on, and any dialog or off-origin request fails the test: the CSP is the backstop, not the fix.

`kind="<script>…"` or `kind=x"/onmouseover="…"` injected elements or handlers into the SVG; the class is now escaped, and the kind becomes one `k-` token
(`[^\w-]` runs read as `-`), so `kind="x sr"` cannot add the page's own classes either. (2) Image
sources were judged as written, not as a browser parses them, so `/\host/a.png`, a leading control character (`\u0001//host/a.png`)
and `https:host/a.png` loaded remotely without `--allow-remote`, and `\u0001javascript:` reached `src`; the parser and renderer now
share `browserUrl` and `imageSrcKind` in core. `\` is read as `/` only where the browser does, in a path or a special-scheme
URL, so `data:image\svg+xml,…` is a non-image `data:` URI and E `image-src`. (3) The sanitizer kept non-image `data:` URLs on `<img src>`; they are now dropped.
The page CSP blocked (1) and (2) on full pages; `fragment` output and a host that strips the meta were exposed.

`@accent`: W `accent-value` for anything but `#rgb`, `#rgba`, `#rrggbb` or `#rrggbbaa` (it was ignored silently, and 5- or 7-digit
values reached the CSS as invalid custom properties). W `accent-contrast` when the accent is under 4.5:1 against the page background,
card surface or note tint, with `detail` `{accent, theme, ratio, required, against}`. 4.5:1 because the accent is text (links,
note labels, picked headers); 3:1 non-text is named in the message when that fails too. Only the theme the accent lands on is checked:
measured in Chromium, the override loses to the dark block's selector, so with no `@theme` dark mode keeps the house accent and only
light is checked; `@theme dark` checks dark. The check runs in `end()`, so `@theme` may follow `@accent` and stream snapshots agree.
Rejected: deriving a safe `--accent-ink` automatically. Links use `--accent` itself, so a derived ink would leave the main text use
failing, and pointing links at the ink would change every default page; the writer's color is kept and the warning says which way to
move it. No `--fix`: there is no single right color. The theme surfaces are copied into core (it cannot import the renderer), and a
render-html test pins them to `theme.ts`.

## D59. `lede build --artifact` writes the part of a page the Claude Artifact tool does not supply
The Artifact tool publishes an HTML file as a page of its own: it adds the doctype, `html`, `head` (charset, viewport, a reset) and

inside that wrapper nests a second `html` and `head` in the body and carries a CSP `meta` that browsers ignore there. `--artifact`
writes only `<title>`, the page's `<style>` and its `<main>`. The style and the main are the full page's, byte for byte, so nothing
about the page changes: the same tokens, the `prefers-color-scheme` block guarded by `:root:not([data-theme="light"])` and the

The `lang` and `description` meta tags and the generator tag are dropped; the tool takes the description as a publish parameter. This is
output for one host, not a new format, and it does not change how an ordinary `build` page looks. It does not make Lede suitable for
the Artifact tool's runtime features (a shared database, asking Claude from the page, saved state): those need script, and ordinary
`build` pages have none (D10). The skill's text and trigger are unchanged until a published artifact has been seen to render.
